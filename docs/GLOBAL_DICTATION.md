# 어디서나 Whisper 받아쓰기

macOS의 다른 앱에서 전역 단축키로 녹음을 시작하고, 확정된 텍스트를 원래 입력창에 붙여넣는 기능입니다. Transrator 번역 창을 열어둘 필요가 없습니다. 번역 API나 LLM 문장 교정을 거치지 않고 로컬 Whisper 모델로 인식합니다.

## 처음 사용하기

번역 API 키가 없어도 사용할 수 있습니다. 메인 첫 화면의 **API 키 없이 Mac에서 받아쓰기 → 받아쓰기 준비**, 또는 트레이 메뉴의 **받아쓰기 준비…**를 누르면 준비 화면으로 바로 이동합니다. 이 경로는 클라우드 키를 조회하지 않습니다. 준비 화면은 모델·마이크·권한·저장된 단축키 상태만 확인하며, 다운로드·권한 요청·녹음을 자동으로 시작하지 않습니다.

1. 트레이 메뉴의 **설정… → 받아쓰기**에서 사용할 Whisper 모델을 선택하고 다운로드합니다. Medium, Large V3 Turbo, Large V3의 다운로드·설치 상태를 각각 관리하며, 저장한 모델이 다음 음성 시작부터 실제로 로드됩니다. 전역 받아쓰기·앱 안 음성 입력·앱 자막이 함께 사용하는 설정입니다.
2. 받아쓸 언어를 선택합니다. 기본 언어는 한국어입니다. 짧은 문장을 받아쓸 때는 자동 감지보다 실제 언어를 지정한 상태와 정확도를 비교하세요.
3. **마이크**에서 시스템 기본 마이크 또는 사용할 장치를 선택합니다. 새 장치를 연결했다면 **새로고침**을 누릅니다. 장치 이름이 같아도 내부의 고유 DeviceUID로 구분하고, 지정한 장치가 연결되지 않았다면 다른 마이크로 몰래 바꾸지 않고 오류를 표시합니다.
4. 필요한 경우 이름·회사명·전문 용어를 힌트에 쉼표로 구분해 입력하고 저장합니다. 힌트는 인식에 참고하는 문맥이며, 특정 철자를 강제로 치환하는 사전은 아닙니다.
5. 메모·TextEdit·브라우저 등에서 받아쓸 입력창을 클릭합니다.
6. 기본 단축키 **`Cmd+Ctrl+D`**를 누릅니다. 최초 실행 시 마이크와 손쉬운 사용 권한을 허용한 뒤 다시 시작해야 할 수 있습니다.
7. 상태창이 **녹음 중**으로 바뀐 뒤 말합니다. 모델 준비 중에는 녹음하지 않습니다. 상태창에는 대상 앱 이름과 자동 입력/결과 복사 모드가 표시됩니다.
8. 같은 단축키를 다시 누르거나 상태창의 **완료하고 입력**을 누릅니다. 자동 입력을 지원하지 않는 대상에서는 **완료**로 표시됩니다. 마지막 발화를 확정한 뒤 시작할 때의 입력 위치에 한 번 붙여넣기를 요청하며, 자동 입력을 지원하지 않으면 결과를 복사해 직접 붙여넣습니다.

단축키는 설정의 단축키 탭에서 변경할 수 있습니다. 메시지를 전송하거나 문서를 저장하는 Enter는 자동으로 누르지 않습니다. `Esc` 또는 상태창의 **취소**로 녹음을 버릴 수 있습니다. `Esc`가 다른 앱에서 동작하지 않으면 상태창의 취소 버튼을 사용하세요.

설정 화면의 **권한 상태**에서 마이크·손쉬운 사용 허용 여부를 미리 확인할 수 있습니다. 화면을 여는 동작은 상태 조회만 수행하며 권한을 요청하지 않습니다. **권한 확인/요청**을 직접 눌러 macOS 안내를 연 뒤, 허용 후 다시 확인합니다. **미리보기**는 녹음·모델 로드·권한 요청 없이 받아쓰기 상태창의 모양만 보여줍니다. 녹음 중에는 미리보기를 시작하지 않습니다.

단축키가 다른 앱 또는 Transrator의 다른 기능과 충돌해도 앱과 설정 화면은 열립니다. 등록 경고가 표시되면 **단축키 변경**에서 다른 조합을 지정하고 저장합니다. 단축키 입력 대기 상태에서 취소하거나 설정 창을 닫으면 저장된 단축키를 다시 등록합니다.

현재 한 세션의 녹음은 최대 3분이며, 시간이 지나면 자동으로 마지막 발화를 확정합니다. 긴 입력은 여러 번 나누어 받아쓸 수 있습니다. 한국어·영어는 발화 구간 사이에 공백을 넣고, 일본어·중국어 지정 시에는 구간 사이에 별도의 공백을 넣지 않습니다.

**모델 메모리 유지**는 전역 받아쓰기를 마친 뒤 모델을 메모리에 보관할 시간을 정합니다. 기본은 **5분**이며 **30초·5분·15분·앱 종료까지 유지** 중에서 선택할 수 있습니다. 오래 유지하면 이어서 받아쓸 때 모델을 재사용할 수 있고, 그동안 모델 메모리를 계속 사용합니다. 실제 녹음·추론 중에는 유지 시간이 지났다는 이유로 모델을 해제하지 않습니다.

## 결과 확인과 다음 받아쓰기

자동 입력이 보류되어 **복사하지 않은 결과**가 남았으면, 기존 받아쓰기 단축키를 다시 눌러 전체 결과를 복사합니다. 이 누름은 녹음을 시작하지 않습니다. 복사 성공 후 다음 누름부터 새 받아쓰기를 시작하며, 복사 실패 시 결과는 계속 보관합니다. 자동 입력을 이미 요청한 결과는 기존처럼 한 번의 단축키로 다음 녹음을 시작할 수 있습니다. 실제 입력이 반영되지 않았다면 새로 시작하기 전에 **결과 복사** 버튼을 사용하세요.

**녹음·인식·결과** 모두 읽기 전용 스크롤 영역에서 전체 문장을 확인할 수 있습니다. 내용이 길어지면 창이 일정 높이까지 늘어나고, 더 긴 내용은 내부에서 스크롤합니다. 녹음 중에는 최신 문장을 따라가며, 위로 스크롤해 이전 내용을 읽는 동안에는 위치를 유지합니다. 끝으로 돌아오면 최신 내용 추적을 재개합니다. 결과의 **크게 보기**를 누르면 본문 영역을 더 넓힐 수 있습니다. 결과의 **닫기**는 복사하지 않은 결과가 있을 때 한 번 확인하고, 5초 안에 **버리고 닫기**를 다시 눌러야 폐기합니다. 결과 상태에서 Esc는 폐기하지 않습니다. 미리보기도 복사하지 않은 결과를 덮어쓰지 않으므로 결과를 먼저 처리하거나 닫아주세요. 다른 앱의 일반 Cmd+C/Esc에 새 전역 동작을 추가하지 않습니다.

상태창에는 `00:00 / 03:00`처럼 경과 시간과 최대 녹음 시간을 표시하고, 마지막 15초에는 남은 시간을 안내합니다. 3분 제한으로 끝났다면 완료 이유가 표시됩니다. 새 시작·미리보기 때 현재 마우스가 있는 화면의 하단으로 위치를 갱신하며, 인식 중간 결과가 갱신될 때는 창이 움직이지 않습니다. 트레이 안내도 실제 저장·등록된 단축키와 일시 중지·등록 실패 상태를 반영합니다.

## 권한과 지원 범위

| 항목 | 용도와 동작 |
| --- | --- |
| 마이크 | 사용자가 받아쓰기를 시작한 동안 음성을 수집합니다. |
| 손쉬운 사용 | 현재 입력창 확인, 입력 위치 변경 감지, 붙여넣기 키 이벤트 전송에 사용합니다. |
| 화면 기록 | 전역 마이크 받아쓰기 자체에는 필요하지 않습니다. 기존 영역 캡처·앱 오디오 자막은 별도 기능입니다. |
| Whisper 모델 | 로컬 파일이 필요합니다. 최초 모델 다운로드에는 네트워크가 필요하지만, 다운로드한 모델로 받아쓰는 과정은 로컬입니다. |

암호 입력창에서는 시작하지 않으며, 터미널 앱은 녹음 후 결과를 복사하는 방식으로 사용할 수 있습니다. 터미널 자동 입력은 지원하지 않습니다. 일부 브라우저·Electron 앱·특수 편집기는 macOS 접근성 정보가 충분하지 않아 자동 입력 대신 결과 복사 모드를 사용합니다.

음성 입력·전역 받아쓰기·앱 자막은 하나의 Whisper 엔진을 공유합니다. 다른 음성 기능이 사용 중이면 해당 기능을 먼저 중지한 뒤 시작합니다.

## 입력 위치와 클립보드 보호

- 시작할 때 대상 앱·입력창·선택 범위·텍스트 상태를 기록하고, 입력 직전에 다시 비교합니다.
- 녹음 중 앱을 전환하거나 커서를 옮기거나 입력 내용을 수정하면 자동 삽입을 보류할 수 있습니다. 상태창의 **결과 복사**로 인식된 문장을 복구할 수 있습니다.
- 원래 클립보드의 텍스트·HTML·이미지 등 복원 가능한 표현을 임시 보관합니다. 읽을 수 없는 클립보드 표현이 있으면 자동 붙여넣기를 보류합니다.
- 임시 텍스트와 원본 복원은 macOS의 `currentHostOnly` 옵션으로 현재 Mac에만 둡니다. 원래 클립보드의 기기 간 공유 정책은 조회할 수 없어 복원 시 공유 범위를 넓히지 않습니다. 사용자가 **결과 복사**를 직접 누른 경우에는 일반 복사 동작을 사용합니다.
- 붙여넣기 후 클립보드가 Transrator가 쓴 상태 그대로일 때만 원래 내용으로 복원합니다. 그 사이 사용자가 새로 복사한 내용은 덮어쓰지 않습니다.
- 앱이 종료될 때 아직 복원 대기 중인 클립보드도 같은 소유권 조건을 확인해 즉시 복원합니다. 이전 붙여넣기의 늦은 완료가 더 최근 붙여넣기나 사용자의 복사를 덮어쓰지 않습니다.
- 키 이벤트 전송 성공만으로 대상 앱의 입력 완료를 확인할 수는 없습니다. 상태창에 남아 있는 결과를 확인하고, 반영되지 않았으면 복사 버튼으로 직접 붙여넣으세요. 중복 입력을 막기 위해 자동 재시도하지 않습니다.

녹음 중간 결과는 상태창에서만 갱신합니다. 외부 입력창의 문장을 인식 도중 계속 바꿔 쓰지 않습니다. 포커스와 결과는 해당 세션의 메모리에서 관리하며, 취소되거나 이전 세션에 속한 콜백은 다음 세션에 입력하지 않습니다.

## 개발 중 검증

저장소 루트에서 실행합니다.

```bash
# 의존성 설치와 네이티브 소스 준비
npm ci
git submodule update --init --recursive

# 프런트엔드 검사와 빌드
./node_modules/.bin/tsc --noEmit
npm test
npm run build

# 네이티브 상태·텍스트·보호 규칙 및 benchmark runner 회귀 검사
bash tests/run_native_dictation_tests.sh

# Rust 단위 테스트 및 실제 macOS 네이티브 빌드
cargo test --manifest-path src-tauri/Cargo.toml --lib
cargo build --manifest-path src-tauri/Cargo.toml

# 마이크를 녹음하지 않고 장치 목록 확인
src-tauri/target/debug/tauri-app --list-microphones

# 앱 실행
npm run tauri -- dev
```

네이티브 상태 검사는 마이크나 손쉬운 사용 권한을 요청하지 않습니다. `DictationSession`, `DictationTranscript`, 입력·클립보드 보호 정책, 무음 시간 계산을 직접 검증합니다. 별도의 AppKit 통합 검사는 `NSPasteboard.withUniqueName()`으로 만든 테스트 전용 클립보드만 사용해 텍스트·HTML·PNG·여러 항목의 실제 복원, 새 복사 보호, 중첩된 붙여넣기 완료와 종료 시 복원을 검증합니다. 사용자 일반 클립보드에는 접근하지 않습니다. Python runner 검사는 가짜 로컬 실행 파일과 임시 PCM 파일을 사용하며 모델을 로드하지 않습니다.

## WAV를 사용하는 오프라인 품질 검사

`tests/run_dictation_benchmark.py`는 이미 빌드한 네이티브 CLI의 `--dictation` 경로를 실행합니다. Python 표준 라이브러리만 사용하며 마이크를 켜거나 네트워크에 접속하지 않습니다. 각 샘플은 새 프로세스에서 실행되므로, `wall_ms`에는 모델 로드가 포함되고 `native_processing_ms`에는 포함되지 않습니다. 이 수치는 실제 녹음 종료부터 외부 앱 삽입까지의 지연 시간과 다릅니다.

```bash
# 첫 샘플 하나: 출력 경로를 명시하고 전체 프로세스에 제한 시간 적용
python3 tests/run_dictation_benchmark.py \
  --sample ja_sample_000.wav --limit 1 --timeout 90 \
  --output /tmp/transrator-dictation-single.json \
  --diagnostics-dir /tmp/transrator-dictation-logs

# 10초가 넘는 발화: 여러 구간이 끝까지 누적되는지 확인
python3 tests/run_dictation_benchmark.py \
  --sample ja_sample_002.wav --limit 1 --timeout 90 \
  --output /tmp/transrator-dictation-long.json

# 한 세션 안에서 같은 발화를 반복: 정상 반복을 필터가 제거하지 않는지 관찰
python3 tests/run_dictation_benchmark.py \
  --sample ja_sample_000.wav --limit 1 --repeat-audio 3 --timeout 90 \
  --output /tmp/transrator-dictation-repeat.json
```

기본 모델 위치를 사용하지 않으려면 `--model /경로/model.bin`을 지정합니다. 이 CLI 모델 선택은 앱에 저장된 설정과 별개이므로, 모델별 비교에서는 파일을 명시합니다. 샘플은 기본 3개를 실행하며, `--limit 0`으로 전체 manifest를 실행할 수 있습니다. 각 결과는 CER, 빈 인식 결과, 무음의 잘못된 텍스트 생성, 제한 시간 초과, 네이티브 처리 시간, 전체 실행 시간을 기록합니다. 실패 샘플도 보고서에서 빠지지 않으며 실패 시 종료 코드는 1입니다. `--diagnostics-dir`를 지정하면 각 네이티브 프로세스의 stdout/stderr도 보존하고 JSON에 해당 파일 경로를 남깁니다. 반복 관찰의 문장 횟수는 정확히 일치한 문자열만 세므로, 철자 인식 오류가 있으면 실제 반복 횟수보다 작을 수 있습니다.

CER는 NFKC 정규화 후 대소문자·공백·문장부호 차이를 제외한 문자 편집 거리입니다. 기본적으로 품질 합격선을 가정하지 않습니다. 이전 결과와 비교할 기준이 있으면 `--max-cer`와 `--max-rtf`를 지정할 수 있습니다.

사용자 음성을 검사하려면 로컬 WAV와 정답을 작성한 manifest를 별도로 사용합니다. 빈 `transcript`는 무음에서 텍스트가 생성되는지 검사할 때 사용합니다.

```json
{
  "dataset": "local-personal-samples",
  "language": "ko",
  "samples": [
    {"filename": "ko_001.wav", "transcript": "내일 오전 열 시에 회의를 시작하겠습니다."},
    {"filename": "silence.wav", "transcript": ""}
  ]
}
```

```bash
python3 tests/run_dictation_benchmark.py \
  --manifest /로컬/음성/manifest.json --limit 0 \
  --output /로컬/음성/결과.json
```

보고서에는 정답과 인식 텍스트가 포함됩니다. 개인 음성·보고서는 Git에 추가하지 않고 로컬에서 보관합니다.

10개 중 7개의 정규화 CER는 0%였습니다. 나머지 3개는 `二時間十五分 → 2時間15分`, `八十パーセント → 80%`, `三百 → 300`처럼 숫자 표기의 차이였습니다. 기본 CER 정규화는 숫자의 의미를 치환하지 않으므로 이 차이도 오류로 계산합니다. 이 검사는 발화 샘플만 포함하며 무음에서의 잘못된 생성 여부를 입증하지 않습니다.

25회 반복은 위 명령의 `--repeat-audio 25 --timeout 120`으로 재현할 수 있습니다. WAV를 실시간보다 빠르게 주입하므로 실제 마이크의 3분 자동 종료 타이머를 검증한 것은 아닙니다. 전체 실행 시간은 모델 로드·초기화를 포함하며, 녹음 종료 후 입력까지의 지연 시간으로 해석하지 않습니다.

추가로 Mac에 설치된 Yuna·Kyoko 보이스의 `say -o` 파일 출력을 사용해 아래 샘플을 만들었습니다. 스피커 재생, 마이크 녹음, 음성 다운로드 없이 로컬 파일로만 검사했습니다.

짧은 발화는 약 1초의 고정 추론 비용이 오디오 길이보다 클 수 있어 RTF만으로 반응 속도를 판단하기 어렵습니다. 예를 들어 264ms “네”의 네이티브 처리는 1,146.21ms였습니다. 긴 발화의 RTF와 함께 실제 종료 후 대기 시간을 확인해야 합니다.

추가 네이티브 수명주기 검사는 최신 Swift 브리지와 Whisper 라이브러리를 연결한 별도 실행 파일에서 16개 조건을 통과했습니다. 한 번 로드한 모델로 두 세션을 연속 인식하고, 백그라운드 추론 중 모델 로드·해제를 거절해 기존 컨텍스트를 유지하며, 추론 완료 후 해제·재로드·재인식까지 확인했습니다. 이 검사는 WAV 입력과 임시 Rust 콜백 대체 함수를 사용하므로 실제 마이크나 전역 단축키의 수명주기 전체를 검증한 것은 아닙니다.

이 검사는 모델 없는 기본 CI와 별도로 실행합니다. 기존 로컬 모델과 약 6.7초의 일본어 WAV를 명시하며 모델을 다운로드하지 않습니다. 현재 Cargo 빌드가 보고한 네이티브 라이브러리를 연결하고 임시 실행 파일은 종료 시 정리합니다.

```bash
bash tests/run_native_lifecycle_smoke.sh \
  --model /로컬/whisper모델.bin \
  --wav tests/fixtures/japanese/ja_sample_000.wav \
  --timeout 120
```

저장소의 현재 일본어 manifest는 `gtts-generated` 합성 음성이며 추가 한국어·일본어도 로컬 합성 음성입니다. 이 결과는 한국어 자연 발화, 사용자 고유명사, 소음·외장 마이크 환경의 정확도를 입증하지 않습니다. macOS 받아쓰기와의 비교도 아직 수행하지 않았습니다. 실제로 자주 말하는 한국어·일본어·영어 문장 30~50개를 같은 마이크·환경에서 비교해 CER, 고유명사 오류, 사용자가 고친 횟수, 녹음 종료부터 삽입까지의 지연을 기록해야 합니다.

### 소음과 TV 음성

마이크와 전역 받아쓰기는 RNNoise로 소음을 줄인 신호에서 음성 구간을 찾고, 원본 음성을 인식합니다. TV 속 사람의 대사도 음성으로 인식되므로 사용자 목소리만 선택하는 기능과 구분해야 합니다. 구현·재현 시험·Apple Silicon 가속 확인·화자 분리 후속 계획은 [음질 개선 계획](DICTATION_AUDIO_QUALITY.md)을 참고하세요.
